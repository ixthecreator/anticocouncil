# 迁移到腾讯云开发

本文说明怎样把成员工作台从 Firebase 迁到腾讯云开发（CloudBase，上海地域），让大陆网络无需代理也能登录和同步。公开页面不受影响，仍由 Vercel 托管。

代码里两套云端服务并存，构建时由 `VITE_CLOUD_BACKEND` 选择：不填时仍是现行的 Firebase 版，填 `cloudbase` 才构建云开发版。两套服务的数据互不同步，只在迁移时通过备份文件复制一次。

## 云开发版有哪些不同

| 方面 | Firebase 版（现行） | 云开发版 |
| --- | --- | --- |
| 注册与找回密码 | 邮件里的验证链接 | 邮件里的数字验证码 |
| 登录方式 | 邮箱密码、Google | 邮箱密码 |
| 所有者 | 写在代码里的邮箱 | 成员名单里角色为 `owner` 的一行 |
| 成员管理 | 浏览器直接读写授权记录 | 经云函数 `membership` 核对后写入，列表每 15 秒刷新 |
| 表决 | 可逐人投票 | 只由主持人录入总数，不保存谁投了什么 |

账号无法迁移，因为密码不能从 Firebase 导出。原有成员要用**原来的邮箱**在云开发版注册一次，注册后按导入的成员名单自动恢复角色，不必重新申请。

## 一、开通环境

1. 用完成实名认证的腾讯云账号登录 [云开发平台](https://tcb.cloud.tencent.com/dev)，新建环境，地域选**上海**。套餐与费用以控制台显示为准。
2. 记下环境 ID（形如 `antico-1a2b3c`），后面的步骤和网站构建都要用。

## 二、启用登录方式

在「云开发平台 → 身份认证 → 登录方式」中：

1. 找到「邮箱验证码」，点「配置发件邮箱」，选择「开启邮件代发」并保存。也可以改填自己的 SMTP 邮箱。
2. 开启「用户名密码登录」。网站的邮箱加密码登录走的是这一项。
3. 其他登录方式保持关闭。

没有开启时，网站会提示「此登录方式尚未在云开发控制台启用」或「云开发尚未开启邮件发送」。

## 三、添加安全域名

在「云开发平台 → 环境配置 → 安全来源 → 安全域名」中添加网站的主机名，不带 `https://`：

- 正式站点：`www.anticocouncil.com`、`anticocouncil.com`
- 试用用的 Vercel 预览域名：在 Vercel 对应部署的 Domains 一栏复制

`localhost` 默认已在列表中，本地调试不用添加。修改约 1 至 2 分钟后生效。

## 四、建集合并设置安全规则

在「云开发平台 → 文档型数据库 → 集合管理」中新建下面 11 个集合，名称区分大小写。每建好一个，打开它的「权限管理」，点「切换到安全规则」，粘贴对应文件的内容：

| 集合 | 规则文件 | 含义 |
| --- | --- | --- |
| `meetings`、`issues`、`members`、`activities`、`attendance`、`editorial`、`assets`、`inventory` | [`workspace-records.json`](../cloudbase/rules/workspace-records.json) | 只有已启用的成员可以读写 |
| `workspaceAccess`、`accessRequests` | [`own-records.json`](../cloudbase/rules/own-records.json) | 每人只能读自己的授权和申请，网页不能直接修改 |
| `accessRoster` | [`server-only.json`](../cloudbase/rules/server-only.json) | 网页完全不能访问，只有云函数能读 |

同一份对应关系也写在 [`cloudbase/rules/collections.json`](../cloudbase/rules/collections.json) 里，测试会核对每个集合都有规则。

## 五、部署成员云函数

成员的认领、申请、批准、停用和角色调整都由云函数 `membership` 完成，代码在 [`cloudbase/functions/membership/`](../cloudbase/functions/membership/)。它直接使用所在的环境，不需要填写密钥或环境变量。

用命令行部署（需要 Node.js）：

```sh
npm i -g @cloudbase/cli
tcb login
tcb fn deploy membership --dir cloudbase/functions/membership -e <环境 ID> --install-dependency true
```

也可以在「云开发平台 → 云函数」中新建：从空白创建，名称填 `membership`，运行环境选 Node.js 18 或更高版本；创建后在在线编辑器里放入该目录的 `index.js`、`membership.js` 和 `package.json`，点「保存并安装依赖」。

函数名必须是 `membership`。网站提示「云开发的成员服务尚未部署」时，先检查这一步。

## 六、导入成员名单

1. 在现行站点用所有者或管理员登录，打开账号菜单里的「成员与访问管理」，点「导出成员名单」，得到 `antico-member-roster-日期.jsonl`。每行一位成员，包含姓名、邮箱、角色和启用状态；所有者那一行的角色是 `owner`。待审批的申请不会导出，申请人需要在新站点重新申请。
2. 在「文档型数据库 → `accessRoster`」中点「导入」，选择这个文件，格式选 JSON，冲突处理选 Insert。
3. 文件里有成员邮箱，导入后删除本地副本，不要传到仓库或聊天里。

名单的使用规则：

- 成员用名单上的邮箱注册（大小写不限）后，第一次进入工作台时自动获得名单中的角色和启用状态。
- 每一行只能被一个账号认领。成员换了账号时，在控制台删除这一行的 `claimedBy` 字段，再删除旧账号在 `workspaceAccess` 中的记录。
- 所有者只能在控制台设置：在名单中加一行角色为 `owner` 的记录，或修改 `workspaceAccess` 中的记录。网页上不能授予或撤销所有者。

## 七、构建云开发版网站

在 Vercel 项目的 Settings → Environment Variables 中添加：

| 变量 | 值 |
| --- | --- |
| `VITE_CLOUD_BACKEND` | `cloudbase` |
| `VITE_CLOUDBASE_ENV_ID` | 第一步记下的环境 ID |
| `VITE_CLOUDBASE_REGION` | `ap-shanghai`，不填时默认就是它 |

试用期间只勾选 Preview，并限定到试用分支，这样正式站点和其他预览都不受影响。修改变量后要重新部署才会生效。

本地调试时，把这三个变量写进 `.env.local` 后运行 `bun run dev`。也可以直接运行 `VITE_CLOUD_BACKEND=cloudbase VITE_CLOUDBASE_ENV_ID=<环境 ID> bun run build` 检查构建。

## 八、搬运业务数据

1. 所有者先在云开发版用名单中 `owner` 那一行的邮箱注册，注册后自动成为所有者。
2. 在现行站点「设置 → 导出备份」下载 JSON 备份。
3. 在云开发版「设置 → 导入备份」导入。写入分批进行；中途失败时会提示完成了多少条，重新导入同一个文件即可继续，同编号的记录不会重复。
4. 通知成员用原邮箱在新站点注册一次。

导入时，逐人记录的选票会折算成赞成、反对、弃权的总数，个人选择不会写入云开发。导出备份之后，现行站点上的修改不会自动带过去。正式切换前请选一个没有人编辑的时间，再导出、导入一次；同编号的记录会被更新。

## 九、试用验收

下面每一项都要在云开发版上实际操作一遍：

- 未登录打开 `/portal`，看到登录页，没有报错。
- 用不在名单里的邮箱注册：收到验证码，填写后出现申请表；提交申请后，管理员在成员管理里能看到并批准，对方随即进入工作台。
- 用名单里的邮箱注册：直接进入工作台，角色与名单一致。
- 两个浏览器同时编辑同一条记录：两边的修改都保留。
- 管理员停用一位成员：对方随即失去访问；恢复后可以再次进入。
- 找回密码：收到验证码，设置新密码后自动登录。用没注册过的邮箱找回，界面给出同样的提示，不透露邮箱是否注册。
- 发起表决：只能由主持人录入票数，数据库里没有个人选票。

全部通过后，把第七步的变量也加到 Production 并重新部署，正式站点就切换到云开发版。切换后 Firebase 不再收到新数据；先保留原项目，确认稳定后再决定是否停用。

## 试用中需要确认的事项

以下几点依赖云开发服务的实际行为，代码按文档实现，但只有在真实环境中才能确认：

- 云函数读取账号邮箱：`membership` 用服务端接口查当前账号的邮箱来匹配名单。如果查不到邮箱，名单认领和申请都会失败，需要改用其他方式确认邮箱。
- 账号编号一致：网页读到的账号编号、安全规则里的 `auth.uid` 和云函数取到的调用者编号应是同一个值，授权记录才能对上。
- 安全规则用 `get()` 查授权记录：没有授权记录的账号应被拒绝；实时同步也要遵守同样的规则。
- 实时同步的数量限制：每个页面同时监听 8 个业务集合和 2 个授权集合，接近单个用户的监听上限；记录很多时，单次推送的条数也有上限。
- 密码要求：云开发对密码可能有额外的强度要求，要到填写验证码这一步才会提示。
- 人机验证：短时间内请求过多时，云开发可能要求人机验证，网站目前只会提示稍后重试。
- 大附件：备份里内嵌的附件会写入数据库记录，单条记录过大时导入会失败。附件改存云存储是下一步的工作。
